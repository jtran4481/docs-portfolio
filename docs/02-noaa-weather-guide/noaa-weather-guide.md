# Retrieving 7‑Day Weather Forecasts Using the NOAA API

> **Audience:** Developers building applications that require weather data.
> **Use Case:** Retrieve a 7‑day forecast for any U.S. location using latitude and longitude coordinates.
> **Prerequisites:** `curl` (or your preferred programming language), an internet connection, and a text editor.
> **Last Updated:** July 2026 – API endpoints and response structures verified.

---

## Overview

The National Weather Service (NWS) provides a free, public REST API at `api.weather.gov`. Unlike many modern APIs, it does **not** require an API key for basic usage. However, the NWS enforces a valid `User-Agent` header to identify your application. This prevents abuse and ensures they can reach you if something goes wrong.

This guide walks you through a two‑step process:

1. Look up your geographical grid point using latitude/longitude.
2. Fetch the forecast for that grid point.

After this guide, you'll be able to:
- Make a valid request to the NWS `/points` endpoint using latitude/longitude
- Extract the forecast URL from the returned JSON
- Make a second request to fetch a 7‑day weather forecast
- Identify the most useful fields in the forecast response (`temperature`, `shortForecast`, etc.)
- Recognize and fix the most common NWS API errors (403, 400, 404)

We’ll use Boise, Idaho (lat `43.6150`, lon `-116.2023`) as our running example.

---

## Convert Coordinates to a Grid Point

The NWS API organizes weather data by grid points, not arbitrary coordinates. You must first transform your latitude/longitude into a grid point via the `/points` endpoint.

### Request

```bash
curl -X GET "https://api.weather.gov/points/43.6150,-116.2023" \
  -H "User-Agent: MyWeatherApp/1.0 (contact@myweatherapp.com)"
```

**Parameter Breakdown:**

| Parameter | Type | Description |
| :--- | :--- | :--- |
| `latitude` | Float (decimal) | Latitude in decimal degrees (for example, `43.6150`). |
| `longitude` | Float (decimal) | Longitude in decimal degrees (for example, `-116.2023`). |

> **Caution:** The NWS API uses a strict comma‑separated format (`lat,lon`). Do **not** use semicolons or spaces or these will return a `400 Bad Request` error.

### Expected Response (Excerpt)

The API returns a large JSON object. The most important parts are:

- `properties.relativeLocation` – the nearest city/state (useful for display).
- `properties.forecast` – the URL we’ll use in Step 2.

```json
{
  "properties": {
    "relativeLocation": {
      "properties": {
        "city": "Boise City",
        "state": "ID"
      }
    },
    "forecast": "https://api.weather.gov/gridpoints/BOI/133,86/forecast",
    "forecastHourly": "https://api.weather.gov/gridpoints/BOI/133,86/forecast/hourly"
  }
}
```

> **Note:** The actual grid point identifiers (`BOI/133,86`) are generated by the NWS and will vary by location.

## Fetch the 7‑Day Forecast

Now that you have the `forecast` URL from Step 1, make a second request to retrieve the detailed weather data.

### Request

```bash
curl -X GET "https://api.weather.gov/gridpoints/BOI/133,86/forecast" \
  -H "User-Agent: MyWeatherApp/1.0 (contact@myweatherapp.com)"
```

### Expected Response (Excerpt)

The `periods` array contains the forecast broken down into 12‑hour segments (day/night) for the next 7 days. Below is a more complete excerpt showing the key fields you’ll likely use:

```json

      {
        "number": 1,
        "name": "This Afternoon",
        "startTime": "2026-07-11T13:00:00-06:00",
        "endTime": "2026-07-11T18:00:00-06:00",
        "isDaytime": true,
        "temperature": 104,
        "temperatureUnit": "F",
        "temperatureTrend": null,

        "shortForecast": "Sunny",
        "detailedForecast": "Sunny, with a high near 104. South southeast wind around 7 mph."
      },
      {
        "number": 2,
        "name": "Tonight",
        "startTime": "2026-07-11T18:00:00-06:00",
        "endTime": "2026-07-12T06:00:00-06:00",
        "isDaytime": false,
        "temperature": 68,
```

**Key fields to parse:**

- `name` – for example, `Today`, `Tonight`, `Monday`.
- `temperature` and `temperatureUnit` – high/low for that period.
- `windSpeed` and `windDirection` – useful for travel or outdoor planning.
- `shortForecast` and `detailedForecast` – human‑readable summaries.

## Common Errors & Troubleshooting

Even though the API is free, these issues often trip up first‑time users. Here’s how to handle them.

| Status Code | Problem | Solution |
| :--- | :--- | :--- |
| `403 Forbidden` | **Missing User-Agent:** The NWS requires a valid User-Agent header. | Add `-H "User-Agent: YourApp/1.0 (your@email.com)"` to every request. |
| `400 Bad Request` | **Malformed Coordinates:** Latitude/longitude format is incorrect. | Ensure you use `lat,lon` (for example, `43.6150,-116.2023`). No spaces. |
| `404 Not Found` | **Out of Bounds:** The coordinates are outside the US or its territories. | Verify the location is within the contiguous US, Alaska, Hawaii, or Puerto Rico. |
| `500 Internal Server Error` | **Temporary API issue:** The NWS service is occasionally unreliable. | Implement a retry policy (for example, wait 5 seconds and try again). |

### Rate Limiting & Caching

While the NWS does not publish strict rate limits, they encourage responsible usage. To avoid unnecessary load:

- Cache forecast data for at least 15–30 minutes (forecasts update infrequently).
- If you need to make many requests, consider fetching the **hourly** or **grid** data once and updating periodically.

## What’s Next?

Now that you have the forecast JSON, here are some common integrations:

- Parse and display – Extract temperature, wind, and conditions to show in a mobile or web dashboard.
- Trigger alerts – Check for severe weather keywords (for example, `Thunderstorm`, `Heavy Rain`) and send notifications.
- Combine with other data – Feed temperature into agricultural models or travel route planners.
- Store for analytics – Archive daily forecasts to compare with actual conditions later.

The NWS also provides other endpoints worth exploring:

- `/gridpoints/{office}/{gridX},{gridY}/forecast/hourly` – hourly breakdown (available in the Step 1 response as `forecastHourly`).
- `/alerts/active?point={lat},{lon}` – active weather alerts for your location.
- `/gridpoints/{office}/{gridX},{gridY}/stations` – list of nearby weather stations (use the `observationStations` URL from Step 1).
- `/stations/{stationId}/observations/latest` – current conditions from a specific station (get `stationId` from the station list first).
